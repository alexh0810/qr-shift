# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | `lucide-react` |
| Font | `Space Grotesk` for branded headings only, `Geist` for body/UI, `Geist Mono` for times, PIN, totals, and token-like values |

Design system notes:
- Reuse the existing semantic token layer in `src/app/globals.css`; do not introduce route-specific palettes.
- Keep the current manual Tailwind plus CSS-variable system; Phase 3 should unify surfaces through shared primitives, not a new library.
- Manager-facing routes must share one workspace language across shell, headers, cards, filters, tables, badges, and action bars.
- `/scan/[qr_token]` remains a standalone task surface and must not inherit manager navigation chrome.
- `/admin/create-store` remains distinct from the manager workspace, but should still feel recognizably QRShift.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status-dot offsets, icon-to-label micro gaps |
| sm | 8px | Tight inline spacing, chip padding, stacked label/value pairs |
| md | 16px | Default control padding, card internals, mobile content gaps |
| lg | 24px | Section internals, header padding, grouped action rows |
| xl | 32px | Primary panel padding, workspace gutters, scan cards |
| 2xl | 48px | Major section breaks inside dashboard and reports |
| 3xl | 64px | Page-level separation between major product regions on desktop |

Exceptions: `44px` minimum touch target for icon-only or compact mobile actions; existing semantic radius tokens (`--radius-panel`, `--radius-control`) remain allowed for panels and controls.

Layout rhythm rules:
- Manager workspace outer padding: `16px` mobile, `24px` tablet, `32px` desktop.
- Workspace content width: cap primary manager surfaces around `max-w-5xl`; do not let data UI stretch edge to edge on large screens.
- Header, filter bar, summary row, and table stack with `24px` vertical rhythm on desktop and `16px` on mobile.
- Scan screen should use a narrower `max-w-md` column with large tap targets and fewer simultaneous elements.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 500 | 1.5 |
| Label | 14px | 700 | 1.4 |
| Heading | 28px | 700 | 1.15 |
| Display | 40px desktop / 34px mobile | 700 | 1.0 |

Typography rules:
- Use only two weights in Phase 3: `500` for body and `700` for emphasis, headings, labels, and totals.
- `Space Grotesk` is reserved for workspace page titles, scan success headlines, and selective branded callouts. Do not use it in dense tables, filter controls, or forms.
- `Geist` remains the default for table headings, row content, form labels, filters, buttons, empty states, and helper text.
- `Geist Mono` is required for PIN entry, time values, duration totals, CSV/export-oriented metrics, and QR/store token displays.
- Dashboard and reports section labels should use uppercase micro-labels sparingly, with clear spacing and no decorative overuse.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4f7fb` / dark `#08101f` | App canvas, scan background, workspace base field, large empty areas |
| Secondary (30%) | `#edf2ff` / dark `#0e1930` | Header shells, elevated panels, filter bars, grouped dashboard/report surfaces |
| Accent (10%) | `#245cff` primary with `#1ed7b5` secondary signal | Primary actions, active navigation/state, key metrics, live-status emphasis, restrained QR motif accents |
| Destructive | `#ff6b47` | Clock-out danger emphasis, destructive confirmations, error messaging only |

Accent reserved for: primary CTA buttons, active manager navigation, selected filters, live attendance chips, export emphasis, key summary numerals, PIN focus state, and small QR-geometry accents in headers or panels. Do not use accent as the default fill for every badge, border, or table row.

Color rules:
- Manager workspace should feel calmer than the landing page: mostly dominant and secondary neutrals, with accent used as a clear signal rather than ambient decoration.
- Dashboard live-state emphasis can use the signal accent for positive operational status, but status must still be understandable from copy and iconography.
- Reports should use accent sparingly for totals, export actions, active date/filter states, and editable row focus.
- Scan can use stronger accent contrast than the manager workspace, but must remain visually simple and single-purpose.
- Admin can borrow the electric accent and QR motifs, but should not look like the public landing page hero.

## Workspace and Surface Contract

- The manager-facing product story is locked to `Scan -> Monitor -> Export`.
- Dashboard is the primary visual anchor and should set the shell language reused by reports.
- Dashboard and reports must share:
  - the same page shell width and outer spacing
  - consistent page header structure
  - the same panel radius, border strength, and shadow behavior
  - one common filter/action bar language
  - one common table/card summary language
- Manager workspace navigation should be explicit and lightweight. Use direct route switching between dashboard and reports; avoid hidden navigation or multi-level menus.
- Scan must remain isolated from the manager workspace. No sidebar, workspace tabs, or manager-only controls should appear there.
- Admin create-store should use a branded internal-tool presentation with clearer hierarchy, but remain operational and form-led.

Surface rules:
- Prefer structured borders over heavy blur or oversized shadows.
- Primary manager panels should use restrained radii and confident outlines, not pill-heavy consumer-app styling.
- Summary cards should present numeric information cleanly, with mono numerals and one strong label/value hierarchy.
- Table wrappers must feel deliberate and readable first: clear header band, row rhythm, edit focus state, subtotal treatment, and empty-state messaging.
- QR-inspired motifs may appear in workspace headers, section markers, or utility badges, but never behind dense table data or form inputs.

---

## Interaction Contract

- All core routes must preserve existing behavior for scanning, manager PIN access, real-time status monitoring, payroll range selection, inline report edits, CSV export, and store creation.
- Loading states:
  - Use centered branded loaders for full-screen fetches.
  - Use inline progress affordances inside action buttons for refresh, export, unlock, and submit actions.
- Empty states:
  - Dashboard empty groups should explain the current operational condition plainly, not as generic "no data."
  - Reports empty states must distinguish between `no employees`, `no shifts in selected range`, and `still calculating`.
  - Admin empty/default form state should provide one concise helper sentence and example input shape.
- Error states:
  - Show inline error surfaces inside the current page context where possible.
  - Avoid browser `alert()` for primary user-facing failures in redesigned surfaces.
- Mobile behavior:
  - Primary actions must remain visible without requiring precision taps.
  - Header controls must collapse cleanly into stacked rows rather than compressed micro-controls.
  - Tables may scroll horizontally, but date filters, export, and employee-selection controls must remain usable at phone widths.
- Motion:
  - Use short reveal and state-change transitions only.
  - Avoid bounce, float, long stagger chains, or decorative looping effects on work-critical screens.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Export Payroll Report` |
| Empty state heading | `No shift activity yet.` |
| Empty state body | `Once employees start scanning in and out, QRShift will show live status on the dashboard and build payroll-ready report rows here.` |
| Error state | `QRShift couldn't load this store right now. Refresh the page and try again. If the issue continues, reopen the QR link or return to the dashboard.` |
| Destructive confirmation | `Lock manager access`: `Lock this workspace on this device? You’ll need the manager PIN to reopen it.` |

Copy rules:
- Use plain operational language. The product should sound work-ready, not promotional, inside the app.
- Dashboard copy should emphasize live visibility and current shift status.
- Reports copy should emphasize payroll readiness, selected date range, and export clarity.
- Scan copy should stay short, direct, and employee-simple: name selection, current status, and next action only.
- Admin copy should describe setup steps concretely and keep demo language separate from production-sounding setup language.
