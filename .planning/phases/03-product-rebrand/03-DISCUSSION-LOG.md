# Phase 3: Product Rebrand - Discussion Log

> **Audit trail only.** Do not use as input to planning, research, or execution agents.
> Decisions are captured in CONTEXT.md — this log preserves the alternatives considered.

**Date:** 2026-04-09
**Phase:** 3-Product Rebrand
**Areas discussed:** visual anchor, rebrand depth, optimization priority, surface boundaries, manager workspace, reports alignment, scan direction, admin direction

---

## Visual Anchor

| Option | Description | Selected |
|--------|-------------|----------|
| Scan flow | Make the scan flow the visual anchor so QRShift feels instantly simple and fast. | |
| Dashboard | Make the dashboard the visual anchor so the product feels operational and trustworthy at a glance. | ✓ |
| Reports | Make reports the visual anchor so payroll clarity is the strongest trust signal. | |

**User's choice:** Dashboard, but with mentions of scan and reports to show a complete workflow.
**Notes:** The product story should read as `Scan -> Monitor -> Export`, with the dashboard as the main anchor surface.

---

## Rebrand Depth

| Option | Description | Selected |
|--------|-------------|----------|
| Visual refresh only | Keep layouts mostly the same and focus on styling polish. | |
| Moderate UI redesign | Preserve the core flows but reshape layouts and hierarchy where needed. | |
| Deep redesign | Rethink most screens structurally while keeping behavior intact. | ✓ |

**User's choice:** Deep redesign.
**Notes:** The user wants a true product-surface redesign rather than a paint job.

---

## Optimization Priority

| Option | Description | Selected |
|--------|-------------|----------|
| Speed and simplicity | Maximize quick comprehension and light interface weight. | |
| Operational clarity | Make status, shifts, and actions feel obvious and reliable at a glance. | ✓ |
| Visual impressiveness | Push harder on brand expression and visual wow-factor. | |

**User's choice:** Operational clarity.
**Notes:** Visual expression matters, but clarity should win whenever there is tension.

---

## Surface Boundaries

| Option | Description | Selected |
|--------|-------------|----------|
| Connected product for all screens | Treat scan, dashboard, reports, and admin as one shared shell. | |
| Manager workspace only | Connect dashboard and reports, while keeping scan and admin distinct. | ✓ |
| Standalone task pages | Keep each route mostly independent. | |

**User's choice:** Manager-facing parts should feel like one connected product, but scan is employee-facing only and admin is reserved for the QRShift owner.
**Notes:** Employees should not be able to see dashboard or reports, and admin should remain a separate owner tool.

---

## Manager Workspace Style

| Option | Description | Selected |
|--------|-------------|----------|
| Operational console | Keep the shell very compact and direct. | |
| Polished workspace | Keep it operational, but with stronger branded framing and a more complete product feel. | ✓ |

**User's choice:** Polished workspace.
**Notes:** The manager-facing experience should feel like a real product workspace rather than a utility board.

---

## Reports Alignment

| Option | Description | Selected |
|--------|-------------|----------|
| Strongly unified | Dashboard and reports share shell, headers, cards, filters, and table language. | ✓ |
| Partially unified | Some shared chrome, but reports stay more document-like. | |
| Mostly distinct | Reports prioritize spreadsheet conventions over product-shell consistency. | |

**User's choice:** Strongly unified.
**Notes:** Reports should still preserve payroll usefulness, but visually belong to the same manager workspace.

---

## Scan Direction

| Option | Description | Selected |
|--------|-------------|----------|
| Very minimal and task-first | Almost no extra framing, just a stripped-down flow. | |
| Branded but still focused | Clearly QRShift, but still optimized for speed and employee simplicity. | ✓ |
| More expressive | Stronger visual drama, closer to landing-page brand moments. | |

**User's choice:** Branded but still focused.
**Notes:** The scan route should feel connected to the brand without losing its employee-only simplicity.

---

## Admin Direction

| Option | Description | Selected |
|--------|-------------|----------|
| Light polish only | Keep it obviously internal and simple, just cleaner. | |
| Branded internal tool | Keep it owner-only, but polish it so it still feels like QRShift. | ✓ |

**Notes:** Admin should remain separate from customer and manager flows, but it should not feel unfinished.
