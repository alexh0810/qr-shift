# Phase 2: Landing Page - Discussion Log

**Date:** 2026-04-09  
**Phase:** 02-landing-page

## Questions and Answers

### 1. Hero messaging and first-screen structure
**Question:** What should the first screen optimize for most?

**Options presented:**
- `Clarity first` — Very direct headline, quick explanation, obvious CTA
- `Product punch first` — A bolder, more memorable hero with stronger visual impact, while still explaining the product quickly
- `Trust first` — Lead with a calmer, more credible tone that makes the product feel dependable and business-ready
- `Custom`

**User selection:** `Product punch first`

**Captured decision:** The landing page hero should feel like a stronger branded product moment while still communicating QRShift quickly.

### 2. Proof and trust content
**Question:** Which supporting content should the landing page emphasize most after the hero?

**Options presented:**
- `How it works + core benefits`
- `Best-fit businesses + benefits`
- `Product preview + benefits`
- `Mixed`

**User selection:** `How it works + core benefits`

**Captured decision:** The strongest support content should explain the simple QRShift workflow and its business value.

### 3. CTA behavior and conversion flow
**Question:** How should the calls to action behave on the landing page?

**Options presented:**
- `Public CTAs first, internal demo access de-emphasized`
- `Public CTAs only`
- `Balanced`
- `Custom`

**User selection:** `Public CTAs first, internal demo access de-emphasized`

**Captured decision:** `Request a Demo` and `Contact` should lead, while internal demo/admin access remains available but visually secondary.

### 4. Page depth and section order
**Question:** What kind of landing page should QRShift become in this release?

**Options presented:**
- `Compact one-pager`
- `Fuller one-pager`
- `Very minimal`
- `Custom`

**User selection:** `Fuller one-pager`

**Captured decision:** Phase 2 should create a fuller one-page landing experience rather than a compact proof surface.

### 5. Product preview style
**Question:** How should the landing page show the product itself?

**Options presented:**
- `Static UI preview`
- `Illustrated workflow blocks`
- `Mixed`
- `No product preview`

**User selection:** `Static UI preview`

**Captured decision:** The landing page should use a static UI preview to make the product feel real quickly.

### 6. Section order after the hero
**Question:** Which sequence feels most right?

**Options presented:**
- `Hero -> How it works -> Benefits -> Best-fit businesses -> CTA close`
- `Hero -> Benefits -> How it works -> Best-fit businesses -> CTA close`
- `Hero -> How it works -> Best-fit businesses -> Benefits -> CTA close`
- `Custom`

**User selection:** `Hero -> How it works -> Benefits -> Best-fit businesses -> CTA close`

**Captured decision:** The landing page narrative should move in that exact order unless small implementation refinements are needed for responsiveness.

## Outcome Summary

- The landing page should feel more public-facing and complete than the current Phase 1 proof surface.
- It should lead with stronger product energy, not just stripped-down clarity.
- The content strategy should teach the workflow and value before diving into audience fit.
- Public conversion actions should clearly outrank founder/internal access.
- A believable static product preview is part of the trust-building strategy for this phase.
